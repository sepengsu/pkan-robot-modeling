# Diverse synthetic friction collection

This is **offline synthetic data generation**, using MuJoCo inverse dynamics on
new, seeded kinematic variations of the Wide16 trajectory plans. It does not
collect real motor torque, execute the robot, use ROS bags, or perform closed
loop rollouts. Existing source trial_001–003 states were identical in checked
trajectories, so copying those files as three independent trials would not add
information.

## PowerShell

From `F:\robot_modeling`:

```powershell
.\scripts\collect_friction_data.ps1 -Preview
.\scripts\collect_friction_data.ps1 -Smoke
.\scripts\collect_friction_data.ps1
```

`-Preview` reads the source plans and prints expected counts without writing.
`-Smoke` creates 3 trials × 100 states for AG145 0 kg / T1 in a timestamped
`result/friction_diverse_smoke_*` folder; it is marked partial and unsuitable
for training. The full command writes to
`F:\robot_modeling\data\friction_diverse_v1`. If interrupted, rerunning the
full command verifies finished chunk hashes and resumes unfinished chunks.
Existing output with a different plan or configuration is rejected.

## Matrix and labels

- Seven conditions: bare 0 kg, AG145 and mDPG at 0/0.5/1.0 kg.
- Sixteen Wide16 trajectories, three distinct seeded smooth variations per
  condition and trajectory: **336 trial chunks**.
- Five friction laws: MuJoCo `dof_frictionloss` (dry Coulomb), additional
  viscous damping, smoothed Stribeck, direction-asymmetric friction, and a
  LuGre-style dynamic bristle state. Only the Coulomb labels are generated by
  changing MuJoCo `dof_frictionloss`; the other four are explicit synthetic
  torque laws added to the MuJoCo inverse-dynamics baseline.
- Three severity multipliers (0.5, 1.0, 1.5): **15 scenarios per state**.
- 100 Hz source plans are sampled at 10 Hz. The first and last 30 seconds are
  trimmed. The verified full run contains **1,317,456 state rows** and
  **19,761,840 state-scenario labels**. Train/validation/test contain
  988,092/82,341/247,023 state rows, respectively.

Each trial NPZ contains `time_s [N]`, `features [N,22]`,
`tau_reference_nm [N,6]`, and `delta_friction_nm [N,15,6]`. The target
torque for scenario `k` is `tau_reference_nm + delta_friction_nm[:,k,:]`.
The adjacent JSON and collection manifest record seeds, source and output
SHA-256 digests, trial identity, units, and the exact `scenario_order`.
No raw ROS bags or source CSVs are copied.

The default split keeps all three trials of each trajectory together: train
T1–T11/T15, validation T12, test T13/T14/T16. A completed full run checks
exact feature overlap between these splits and sets `training_ready: true`
only after it passes. Model training should use the group split and fit
normalizers or friction parameters on training rows only.
The full collection passed this audit with zero exact feature overlaps across
the three splits; every scenario label was finite.

## Scope

These three trials are three **generated motion variations**, not repeated
physical experiments. The friction magnitudes and laws are configured
assumptions, not measured A0509 properties. This dataset can benchmark
interpolation or transfer across synthetic friction laws and severity levels,
but cannot establish real robot friction or sim-to-real accuracy. Keep the
existing 21-run J1 compensation pilot separate.
